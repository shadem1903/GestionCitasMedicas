🌐 Actividad Clase 4

Comunicación entre Servicios + REST + Eventos + Service Discovery

Equipo: Equipo de Desarrollo

Proyecto: Gestión de Citas Médicas

🪜 1. Interacciones entre Servicios

Interacción 1

Servicio de Pacientes
Servicio de Citas
Solicitud de nueva cita (ID paciente, especialidad, fecha preferida)
El sistema muestra error al paciente y reintenta la solicitud con timeout

Interacción 2

Servicio de Citas
Servicio de Disponibilidad Médica
Consulta de horarios disponibles para la especialidad en rango de fechas
Se muestra mensaje de indisponibilidad y se invita al usuario a intentar más tarde

Interacción 3

Servicio de Citas
Servicio de Notificaciones
Evento "Cita Creada" con detalles: email paciente, fecha, hora, doctor
La cita se crea igual pero el paciente podría no recibir confirmación inmediata

🪜 2. REST o Eventos

Interacción REST Evento ¿Por qué?
1 ✓ Necesita respuesta inmediata del disponibilidad
2 ✓ Consulta de datos en tiempo real
3 ✓ Publicar el evento para que otros servicios lo procesen

🪜 3. Síncrono o Asíncrono

Interacción Síncrono Asíncrono Justificación
1 ✓ El paciente espera confirmación de la solicitud
2 ✓ Consulta de disponibilidad requiere respuesta inmediata
3 ✓ No es crítico si se demoran las notificaciones

🪜 4. Eventos Importantes del Sistema

1️⃣ CitaCreada: Se publica cuando una cita es reservada exitosamente

2️⃣ CitaCancelada: Se publica cuando un paciente o doctor cancela una cita

3️⃣ CitaProxima: Se publica 24 horas antes de una cita para reminder

🪜 5. Análisis de Fallos

Servicio de Disponibilidad Médica
Los usuarios no podrían reservar citas y el servicio de citas no funcionaría
El sistema debe continuar con cache de datos anteriores o modo degradado
Implementar reintentos automáticos, circuit breaker, fallback cache, y alertas al ops

🪜 6. Service Discovery

El servicio cliente seguiría intentando conectar a una IP inválida y fallaría
A través de un Service Discovery (Consul, Eureka, DNS) que mantiene registro actualizado
Permite escalabilidad automática, rebalanceo de carga y tolerancia a fallos
En todas las interacciones: Citas descubre Disponibilidad, Notificaciones, y Pacientes

🪜 7. Mini Diagrama

Dibujen:

Servicio A → Service Discovery → Servicio B

💡 Ayuda rápida
REST → petición directa
Evento → algo ocurrió
Síncrono → espera respuesta
Asíncrono → continúa sin esperar
Service Discovery → permite encontrar servicios automáticamente
🎤 El equipo debe poder explicar:
✔ una interacción importante
✔ un evento del sistema
✔ qué pasa si un servicio falla
✔ dónde usarían Service Discovery
